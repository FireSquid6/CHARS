# CFBD server adapter

Use `createClient()` only from server jobs. Set `CFBD_API_KEY` in the server environment; never use `NEXT_PUBLIC_` or serialize the client. Inject `fetch`/`apiKey` only in offline tests. Missing keys and invalid payloads fail closed. A request has a 10-second timeout and at most two retries for transport failures, 429, and 5xx; 429 `Retry-After` is honored up to 30 seconds. Callers should also rate-limit season requests against their own CFBD quota. No database writes or game inclusion/classification decisions happen here.

Schema checked against the live CFBD Swagger document at `https://api.collegefootballdata.com/swagger/swagger-ui-init.js` on October 19, 2026: `Game`, `Team`, `PollWeek`, `Poll`, `PollRank`, `CalendarWeek`, and the `/games`, `/teams`, `/teams/fbs`, `/rankings`, `/calendar` query parameters. A valid key was not available to check authenticated production samples. Parsers validate the fields required by this adapter and retain full source objects (including extra fields); no rank release timestamp is documented, so `releasedAtUtc` is `null`. Provider `seasonType` remains provider metadata, never application CCG/regular classification. Unfinished scores, even 0–0, are not final results. Poll rank `null` and tied ranks are retained. A season's FBS membership comes from `/teams/fbs?year=...`, never today's roster. Null classification stays `unknown` unless the season roster establishes FBS membership. Missing FBS provider IDs fail resolution; FCS visitors absent from `/teams` can be resolved by game provider ID and game-side classification. No name-based game joins are made.

`games(year)` returns `{ items, sources: [fbsSource, fcsSource] }`, **not** a single-source response. Each source has its own URL, observation time, raw payload and parsed items. Overlapping provider game IDs must have identical raw content. The merged result can include unrelated FCS–FCS games: before ingestion, use `filterFbsGames(items, seasonFbsIds)` with the validated season roster to retain only games with at least one FBS participant (including FBS–FCS). Preserve both source payloads for audit. Callers must check per-season coverage and release timing before publishing snapshots.

The documented Game schema supplies `completed` but no status field. If a response includes a recognizable status, the adapter uses it; notes saying cancelled/postponed are provisional evidence. Contradictory evidence or an unrecognized status produces `unknown` with normalized `completed: false`, retaining all original fields in `raw`; downstream code must not treat that as a played tie. An unfinished game without a status is also `unknown`, not necessarily scheduled. A malformed HTTP 200 response fails validation immediately rather than being retried: repeating a schema mismatch can waste quota and conceal an upstream contract change.
