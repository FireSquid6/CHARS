# CFBD server adapter

Use `createClient()` only from server jobs. Set `CFBD_API_KEY` in the server environment; never use `NEXT_PUBLIC_` or serialize the client. Inject `fetch`/`apiKey` only in offline tests. Missing keys and invalid payloads fail closed. A request has a 10-second timeout and at most two retries for transport failures, 429, and 5xx; 429 `Retry-After` is honored up to 30 seconds. Callers should also rate-limit season requests against their own CFBD quota. No database writes or game inclusion/classification decisions happen here.

Schema checked against the live CFBD Swagger document at `https://api.collegefootballdata.com/swagger/swagger-ui-init.js` on October 19, 2026: `Game`, `Team`, `PollWeek`, `Poll`, `PollRank`, `CalendarWeek`, and the `/games`, `/teams`, `/teams/fbs`, `/rankings`, `/calendar` query parameters. A valid key was not available to check authenticated production samples. Parsers validate the fields required by this adapter and retain full source objects (including extra fields); no rank release timestamp is documented, so `releasedAtUtc` is `null`. Provider `seasonType` remains provider metadata, never application CCG/regular classification. Unfinished scores, even 0–0, are not final results. Poll rank `null` and tied ranks are retained. A season's FBS membership comes from `/teams/fbs?year=...`, never today's roster. Missing FBS provider IDs fail resolution; FCS visitors absent from `/teams` can be resolved by game provider ID and game-side classification. No name-based game joins are made. The two classification game queries are kept as separate sources for ingestion provenance; overlaps must agree and are merged by provider game ID. Callers must check per-season coverage and release timing before publishing snapshots.
