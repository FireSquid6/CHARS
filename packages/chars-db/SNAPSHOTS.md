# Offline snapshot publication

Run `bun run db:migrate` and `bun run snapshots:rebuild --season YEAR` after ingesting a season. No CFBD key is required for rebuilding already-normalized data. The command returns published, unchanged and incomplete snapshot keys. A missing trustworthy pre-CCG poll, unresolved regular game, unknown classification, incomplete season coverage, calendar gap, or unverified freeze blocks **new final** publication; an older successfully published final remains readable. Weekly snapshots may be published with explicit incomplete coverage reasons and must not be interpreted as proved final selections or scenario statuses.

Game cutoff and poll cutoff are distinct. Historical games lacking a completion timestamp are reconstructed only once their calendar week closes; this is not a claim that the source reported them on that date. Poll timing marked `derived_convention` maps provider game-week N to the next regular calendar window after game week N-1. When no such window exists before the first CCG, `derived_pre_ccg_cutoff` maps **only** the poll labeled N+1 for the last full regular weekend N to the first CCG kickoff as an **upper-bound convention**. It does not assert publication at kickoff or establish the actual release time; a known release timestamp at or after kickoff is rejected. The poll must exist in the regular-season source and there must be no later full regular weekend before the CCG. A final snapshot requires this corresponding AP poll before 2014 or CFP poll thereafter, and an independently classified first CCG after the freeze. Earlier CFP-era weekly views may use AP until an eligible CFP release exists. Post-CCG releases and future game scores never enter the frozen input. The persisted coverage JSON records these conventions and poll provenance.

`snapshot_publications` is the atomic current-revision pointer. Readers must join this table to `snapshots`, then join results by **both** snapshot key and revision; do not read `MAX(revision)` or current `games` for an old published result. Ingestion's broad invalidation hints are cleared only after verified unchanged inputs or successful replacement. The builder checks each calendar snapshot in order and skips unchanged hashes, so corrections rebuild from the earliest affected snapshot without recalculating unchanged earlier results. Input and policy hashes, included game revisions, rankings, swaps, and bracket slots commit together. The current `site` has no database-backed cached season pages yet; once added, those routes must use revision-keyed cache entries or explicit Next cache invalidation after publication (not before commit).
