# Offline snapshot rebuild (limited)

Active-season sync passes its current UTC time to snapshot construction and republishes unchanged source data when the local day or an in-day week boundary changes, rather than regenerating on every same-day run. The importer records a proposed `source/YEAR-calendar-candidate.json` only when an explicitly classified CCG and a non-overlapping regular calendar window support a cutoff; its `verified: false` is intentional. An ambiguous calendar has a null candidate. Neither candidate is promoted to the operator-owned `YEAR-calendar.json` automatically.

`bun run snapshots:rebuild --season YEAR` reads the **existing** SQLite tables from `DATABASE_PATH` (default `chars.sqlite`) and writes content-addressed artifacts and a last-successful manifest under `CHARS_CACHE_PATH/snapshots/YEAR` (default `.cache`). `.cache` is ignored by git. No migrations or schema changes are required. Consumers must read `current.json` first and then only its listed keys; a failed rebuild does not change the manifest. Store the cache on durable storage if snapshots must survive a restart. Sync loads the operator-verified calendar and republishes on verification changes or when a manifest is missing; manual rebuild uses the same calendar, metadata, audit gaps and pending-journal checks. Scheduled sync uses a cache-directory lease with a heartbeat/live-owner check; manual snapshot rebuild has no cross-process lease, and neither path transactionally couples SQLite writes to filesystem publication.

Without trusted metadata, score pairs are **not** proof of completion; games are treated as scheduled, and coverage reports unverified classification/completion. The server-only CFBD importer (`data:backfill` / `data:sync`) validates bearer-authenticated season inputs, upserts regular-season rows into the unchanged SQLite schema, and writes `.cache/source/YEAR-games.json`: an object keyed by decimal game ID with `SourceGameMetadata` fields (`providerSeasonType`, `applicationGameType`, `classificationSource`, `status`, `completed`, `payloadHash`). Postseason evidence, raw responses, hashes, coverage and revision copies live in `.cache/source/YEAR-audit.json` and `.cache/source/revisions/`. With no trusted importer metadata, an operator may supply the game sidecar only after validation, never by guessing completion from scores. The games table is contractually regular-season-only; no field in it can distinguish an unfinished 0–0 from a tie. SQLite upserts are transactional, but SQLite and sidecar files cannot commit atomically. A `YEAR-pending.json` journal left after interruption requires operator review: inspect its `phase` (`prepared` or `db-committed`), compare its audit to SQLite and the game/audit sidecars, restore/reconcile any incomplete handoff, and only then clear the journal and retry. `prepared` does **not** prove the transaction did not commit if the crash happened between commit and phase update. Do not delete the journal blindly or claim a coherent publication. Ambiguous classifications/identity, missing prior source rows and poll-timing gaps prevent automatic sync publication, leaving the previous snapshot manifest in place. No live historical completeness verification or automatic crash reconciliation is provided.

An optional `.cache/source/YEAR-calendar.json` has `freezeUtc`, `firstCcgUtc` (ISO UTC strings), and `verified: true`. The CFBD importer stores a **derived upper bound**, not an actual publication time, in `poll_releases.released_at`. A final therefore also requires separately operator-reviewed `.cache/source/YEAR-poll-timing.json`, keyed by the exact `release_id`. Each entry needs `reviewedBy`, `reviewedAtUtc`, `source` (a citation to independent publication evidence), `pollFingerprint`, and **either** `releasedAtUtc` **or** `interval: { earliestUtc, latestUtc }`, all UTC ISO strings. Compute the fingerprint with exported `pollFingerprint(poll)` from `src/snapshots.ts` on the current database release and entries; a changed poll invalidates prior timing review. The entire reviewed interval must be within `[freezeUtc, firstCcgUtc)`. A derived bound or an interval crossing CCG does **not** suffice. The sidecar is never generated by ingestion; a change to it invalidates the sync calendar marker without modifying SQLite. A final is emitted **only** if these cutoffs are ordered, membership/schedule/classification and completion coverage have no unresolved warnings, and a nonempty reviewed CFP (2014 onward) or AP (earlier) release qualifies. For the active season the final also waits until the CCG cutoff has passed. `verified` is an operator assertion, not a conclusion from the database. Do not mark a calendar verified without checking the full season schedule against an authoritative source. Weekly snapshots can use an unverified derived poll upper bound but label its uncertainty in coverage; a verified actual release after the weekly cutoff cannot be used merely because the stored bound is earlier. Missing or stale polls are disclosed in weekly coverage; 2014+ weekly views use the latest available AP poll when CFP is not yet released, but finals do not. No later poll or game result enters an earlier weekly calculation. Historical weekly reconstruction uses kickoff and poll-release upper bounds, **not** the provider's historical observation times. Active-season builds default to the current UTC time; `snapshots:rebuild --season YEAR --as-of YYYY-MM-DDTHH:mm:ss.sssZ` can supply a cutoff for reproducible active-season rebuilds. Preseason gets an empty partial snapshot. Current-week partial snapshots omit that week's results because the existing source lacks completion-observation timestamps, and mark the omission incomplete. Previously closed weeks retain the retrospective reconstruction convention, not an assertion of when results became known. The absence of a scenario proof is always `pending`, never an elimination claim.
