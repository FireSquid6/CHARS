# Offline snapshot publication

Run `bun run db:migrate` and `bun run snapshots:rebuild --season YEAR` after ingesting a season. No CFBD key is required for rebuilding already-normalized data. The command returns published, unchanged and incomplete snapshot keys. A missing trustworthy pre-CCG poll, unresolved regular game, previously observed but now missing game ID, unknown classification, incomplete season coverage, calendar gap, or unverified freeze blocks **new final** publication; an older successful final remains readable with `publicationState: "stale"`. Missing rows are not cancellations. Pending/obsolete weekly keys are hidden; weekly results with gaps are marked incomplete and cannot prove scenario statuses.

Game cutoff and poll cutoff are distinct. Historical games lacking a completion timestamp are reconstructed only once their calendar week closes; current partial snapshots can include a completed score without a completion timestamp only if a validated observation of that completed game was seen between kickoff and the partial cutoff. Neither convention asserts earlier knowledge. Poll timing marked `derived_convention` maps provider game-week N to the next regular calendar window after game week N-1. When no such window exists before the first CCG, `derived_pre_ccg_cutoff` maps **only** the poll labeled N+1 for the last full regular weekend N to the first CCG kickoff as an **upper-bound convention**. It does not assert publication at kickoff or establish the actual release time; a known release timestamp must be after the game cutoff and strictly before the poll cutoff. The poll must exist in the regular-season source and there must be no later full regular weekend before the CCG. A final snapshot requires this corresponding AP poll before 2014 or CFP poll thereafter, and an independently classified first CCG after the freeze. Earlier CFP-era weekly views may use AP until an eligible CFP release exists. Post-CCG releases and future game scores never enter the frozen input. The persisted coverage JSON records these conventions and poll provenance.

`snapshot_publications` is the atomic current-revision pointer. Readers must join this table to `snapshots`, then join results by **both** snapshot key and revision; do not read `MAX(revision)` or current `games` for an old published result. Ingestion advances `season_input_generations` atomically on material source changes and marks publications pending/stale. The builder reads a consistent SQLite WAL snapshot, computes without a writer lock, then rechecks the generation in its publication transaction; a change reports a retryable gap without publishing stale results. Broad invalidation hints clear only after verified unchanged inputs or successful replacement. The builder checks each calendar snapshot in order and skips unchanged hashes. Input and policy hashes, game revisions, rankings, swaps, and bracket slots commit together. The `site` has no database-backed cached season pages yet; once added, those routes must use revision-keyed cache entries or explicit Next cache invalidation after publication (not before commit).
