# Season backfill (server only)

Set `CFBD_API_KEY` and an absolute, durable `DATABASE_PATH`. Run `bun run data:backfill --season 1998` or `bun run data:backfill --from 1998 --to CURRENT`. `CURRENT` is the football season in America/Chicago (January–June remains the preceding fall season). Migrations run automatically. A missing key fails before database creation. The command prints one JSON report per committed season; a validation or SQL failure rolls that season back. Earlier seasons already committed in a range remain committed.

Each request is observed separately with raw JSON, SHA-256, source URL and UTC fetch time; game revisions refer to the exact source observation and preserve previous normalized values. Replaying identical games adds observations but not revisions. Empty or missing schedules are flagged and existing games are **not** deleted. No inferred cancellation from an absent row. Stable provider IDs join games to season-specific rosters. FCS opponents are retained. Unfinished scores, including 0–0, are cleared from normalized score columns; the provider status is preserved in `provider_status_evidence` when the base status constraint requires an unknown to be represented as scheduled.

Game classification is conservative: explicit conference-championship, bowl and playoff markers take precedence; a regular game requires both provider regular type and a matching regular calendar window without contradictory markers. Otherwise it is unknown, and coverage is incomplete. The pre-CCG freeze requires an identified CCG and the last wholly preceding regular calendar week. Missing CCG evidence does not create an invented freeze. The provider's AP/CFP response has no release timestamps: `released_at_utc` and `effective_at_utc` are null with explicit timing provenance. Ties and unranked poll entries are retained; no historical date is guessed from a week number. Calendar and roster/schedule/classification/poll/timing/freeze coverage are persisted in `seasons.coverage_json`; the season is marked `incomplete` until separate validation and snapshot publication can establish completeness. This importer does not publish rankings or claim the 1998–current historical dataset is complete.

`gamesAtCutoff` requires a completed explicitly regular game whose kickoff and **entire calendar week** precede the cutoff; `pollsAtCutoff` excludes undated releases. These are conservative reconstruction guards, not proof that results were already reported by CFBD on a historical date. The normalized games table stores the latest correction; snapshot builders must pin `game_revisions` and their declared cutoffs, and must never reinterpret later observations as contemporaneous API archives.
