# Season backfill (server only)

Set `CFBD_API_KEY` and an absolute, durable `DATABASE_PATH`. Run `bun run data:backfill --season 1998` or `bun run data:backfill --from 1998 --to CURRENT`. `CURRENT` is the football season in America/Chicago (January–June remains the preceding fall season). Migrations run automatically. A missing key fails before database creation. The command prints one JSON report per committed season; a validation or SQL failure rolls that season back. Earlier seasons already committed in a range remain committed.

Each request is observed separately with raw JSON, SHA-256, source URL and UTC fetch time; game revisions refer to the exact source observation and preserve previous normalized values. Replaying identical games adds observations but not revisions. Empty or missing schedules are flagged and existing games are **not** deleted. No inferred cancellation from an absent row. Stable provider IDs join games to season-specific rosters. FCS opponents are retained. Unfinished scores, including 0–0, are cleared from normalized score columns. Unknown/contradictory provider game statuses abort the entire season transaction before any write; no unknown status is normalized to scheduled.

Game classification is conservative: explicit conference-championship markers or a championship named for a conference in the season roster, bowl and playoff markers take precedence; a regular game requires both provider regular type and a matching regular calendar window without contradictory markers. Otherwise it is unknown, and coverage is incomplete. The pre-CCG freeze requires an identified CCG and the last wholly preceding regular calendar week. Missing CCG evidence does not create an invented freeze. The provider's AP/CFP response has no release timestamps: `released_at_utc` remains null. **Weekly reconstruction convention:** a week N regular-season poll can be assigned the start of calendar week N only when regular weeks N-1 and N exist, do not overlap, and week N begins before the known CCG. This is stored as `effective_at_utc` with `timing_provenance=derived_convention`, not as an observed release time. Otherwise timing remains unknown and the poll is unavailable to temporal queries. Ties and unranked poll entries are retained. Corrected polls supersede their old season/type/week version; only the current version is eligible for temporal lookup. Calendar revisions are retained, and changes/missing/additional weeks, game revisions, and poll revisions/timing changes record snapshot invalidations. Rebuild workers must consume those invalidations before treating old published outputs as fresh. Season roster/schedule/classification/poll/timing/freeze coverage is recorded in `season_ingestion_gaps`; a previously final `seasons` row is not downgraded or replaced by an incomplete replay. This importer does not publish rankings or claim the 1998–current historical dataset is complete.

`gamesAtCutoff` requires a completed explicitly regular game whose kickoff and **entire calendar week** precede the cutoff. If a valid provider `endDate` is present it must also precede the calendar week's end and cutoff; otherwise inclusion is labeled `reconstructed_week_final` rather than falsely claiming historical completion timing. `pollsAtCutoff` excludes unknown-timing and superseded releases. These are conservative reconstruction guards, not proof that results or polls were already reported by CFBD on a historical date. The normalized games table stores the latest correction; snapshot builders must pin `game_revisions` and their declared cutoffs, and must never reinterpret later observations as contemporaneous API archives. Invalidation tracking is conservative (all published snapshots in the affected season); exact affected-week rebuild and atomic replacement are later steps.
